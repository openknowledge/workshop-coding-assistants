== Kontext und Problembeschreibung

Ein einheitlicher Git-Workflow sorgt für eine saubere, nachvollziehbare Commit-Historie. Dadurch lassen sich Änderungen leichter nachverfolgen und Code-Reviews werden übersichtlicher.

== Entscheidungstreiber

* Saubere, lineare Commit-Historie
* Nachvollziehbare Änderungen pro Ticket
* Einfache Zuordnung von Commits zu Tickets

== Diskutierte Optionen


. Rebase + Squash vor Merge Request

== Ergebnis

Wir verwenden Rebaase + Squash vor dem Merge Request

== Vor- und Nachteile

[cols="1,1"]

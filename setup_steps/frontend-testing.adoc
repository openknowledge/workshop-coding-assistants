= Frontend-Testing mit Playwright

== Warum Playwright?

**Playwright** ist ein End-to-End-Testframework von Microsoft, das Browser-Interaktionen automatisiert und damit das gesamte Frontend – inklusive Routing, API-Kommunikation und UI-Verhalten – in einer realistischen Umgebung testet.

Gute Tests testen das fachliche Verhalten und keine Implementierungsdetails. Im Gegensatz zu rein unit-basierten Ansätzen stellt Playwright sicher, dass die Anwendung aus Nutzerperspektive korrekt funktioniert.

=== Ausnahme: Vitest und Testing Library

Für einzelne UI-Komponenten können *zusätzlich* Tests mit **Vitest** und **Testing Library** geschrieben werden.
Diese sind optional und ergänzen die Playwright-Tests – sie ersetzen sie nicht.
Sinnvoll sind sie vor allem für Komponenten mit komplexer interner Logik, die sich isoliert gut testen lassen (z.B. Formularvalidierung, Fehleranzeigen).

== Ordnerstruktur

[source]
----
basisprojekt-client/
  e2e/                          # Playwright End-to-End-Tests
    customers/
      customers.spec.ts         # Tests für das Customer-Feature
    global-setup.ts             # Startet den Backend-Stack via testcontainers
    global-teardown.ts          # Fährt den Stack nach den Tests herunter
    dockerEnvironment.ts        # Teilt die Compose-Environment-Referenz zwischen Setup/Teardown
  src/
    features/
      customers/
        components/
          CustomerForm.test.tsx # Optionaler Vitest-Komponententest
    test/
      setup.ts                  # Vitest-Setup (Jest-DOM-Matcher)
  playwright.config.ts
----

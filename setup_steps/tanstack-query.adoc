= TanStack Query Setup

== Warum TanStack Query?

**TanStack Query** ist eine Bibliothek für asynchrones State-Management in React.
Im Vergleich zu manuellem Datenabruf mit `useEffect` und `useState` übernimmt TanStack Query automatisch Caching, Hintergrundaktualisierungen, Ladezustände und Fehlerbehandlung –
und ermöglicht dabei typsichere Query-Definitionen über `queryOptions`.

== Installation

----

== Ordnerstruktur

Für jedes Feature gibt es eine dedizierte API-Schicht unter `src/features/<feature>/api/`,
die in zwei Dateien aufgeteilt ist:

[source]
----
src/
  features/
    customers/
      api/
        customerApi.ts      # Fetch-Funktionen (HTTP-Aufrufe)
        customerQueries.ts  # TanStack Query Hooks und queryOptions
----

`customerApi.ts` enthält ausschließlich die Fetch-Funktionen.
`customerQueries.ts` definiert die Query Keys, `queryOptions` und Mutation Hooks.

== QueryClient einrichten

Der `QueryClient` wird einmalig in `main.tsx` erstellt und über den `QueryClientProvider` der gesamten Anwendung bereitgestellt.
Über `defaultOptions.queries.staleTime` wird festgelegt, wie lange gecachte Daten als aktuell gelten.

Der `queryClient` wird außerdem als Router-Kontext übergeben, damit Routen-Loader
Daten vor dem Rendern vorladen können.

== Query Keys und queryOptions

Query Keys identifizieren gecachte Daten eindeutig.
Sie werden in einem zentralen `customerKeys`-Objekt definiert, um Konsistenz sicherzustellen.

`queryOptions` fasst Query Key und Query-Funktion zusammen und liefert ein typsicheres Objekt,
das sowohl in Routen-Loadern als auch in `useSuspenseQuery` verwendet werden kann.

=== Vorladen mit dem Routen-Loader

Dadurch werden die Daten geladen, bevor die Komponente gerendert wird,
sodass kein Ladezustand in der Komponente behandelt werden muss.

== Daten mutieren

`useMutation` kapselt den HTTP-Schreibaufruf.
Nach erfolgreicher Mutation werden betroffene Queries über `queryClient.invalidateQueries` invalidiert,
sodass TanStack Query die Daten automatisch neu lädt.
